## Context

Мотивация — см. `proposal.md` → Why. Требования — см. `specs/`.

Что важно знать про систему, чтобы понять решения ниже:

- **Контент живёт только в production.** Репозиторий содержит тему и плагины; база и медиатека в git не попадают. Деплой — FTP-синк `wp-app/` → `public_html/` из `.github/workflows/main.yml` при пуше в `main`. Значит две из трёх задач — это правки в wp-admin на боевом сайте, и в репозитории от них не останется следа, кроме этих артефактов.
- **Главная собрана ACF-блоками.** Слайдер — блок `acf/slider` (`modules/slider/slider.php`), слайды лежат в ACF-репитере `slider` на странице. Сейчас три слайда: `Банер-электрогаз-рус.png`, `Житомир-10-рус.png`, `slide-1-scaled.jpg`.
- **Swiper 5.3.7** (`assets/js/libs/swiper.min.js`). В пятой версии `watchOverflow` по умолчанию `false`; классы `swiper-button-lock` / `swiper-pagination-lock`, которые прячут управление, навешиваются только при `watchOverflow: true`.
- **Меню категорий нигде не задано руками.** `header.php` и `components/category-template.php` берут термы через `get_terms(..., 'hide_empty' => true)`, `footer.php` — через `object_ids` опубликованных товаров, а `Helpers::getProductsByCategory()` жёстко фильтрует `post_status => 'publish'`. То есть видимость раздела целиком производна от статуса его товаров.
- **Production — nginx + PHP 8.2**, страницы кешируются (в ответах есть заголовки `wpo-cache-*`, то есть на сайте работает WP-Optimize, которого нет в репозитории). `.htaccess` на nginx не читается.

## Goals / Non-Goals

**Goals:**

- Свести правки в коде к минимуму: в код идёт только то, что без кода не чинится (поведение слайдера при одном слайде, редиректы).
- Сделать удаление раздела обратимым и не потерять внешние ссылки на снятые URL.
- Убрать зависимость баннера «Электрорезерв» от доступности `atem.ua`.

**Non-Goals:**

- Не переносим контент главной или карточек товаров в код/миграции — принятый в проекте способ управления контентом остаётся прежним.
- Не чиним остальные хотлинки на `atem.ua` (ещё три картинки на Житомир-9 и другие карточки) — отдельное изменение.
- Не вводим плагин редиректов и не трогаем конфигурацию nginx на хостинге.

## Decisions

### 1. Слайды удаляем из ACF, а не прячем кодом

Правим репитер `slider` на главной в wp-admin: убираем первую и последнюю строки.

*Альтернатива:* отфильтровать слайды по имени файла в `slider.php`. Отклонено — зашивает контентное решение в шаблон, редактор потом не поймёт, почему добавленный слайд не выводится.

### 2. `watchOverflow: true` в `modules/slider/slider.js`

После правки №1 на главной остаётся один слайд, и Swiper 5 по умолчанию продолжит рисовать стрелки, точку пагинации и крутить автоплей по пустому месту. `watchOverflow: true` заставляет Swiper заблокироваться и навесить `*-lock`-классы, которые уже прячут управление штатными стилями `assets/style/libs/swiper.scss`.

*Альтернатива А:* спрятать стрелки и пагинацию правилом CSS на `.slider`. Отклонено — автоплей и обработчики свайпа останутся живыми, и решение сломается, когда слайдов снова станет несколько.
*Альтернатива Б:* ничего не делать. Отклонено — остаются нерабочие на вид элементы управления, это заметный визуальный дефект на главной.

Правка затрагивает все слайдеры с классом `.gallery-swiper`; на момент изменения это только слайдер главной.

### 3. АРБАТ — в черновик, терм не удаляем

Товару АРБАТ ставим статус «Черновик». Этого достаточно: все три места вывода категорий фильтруют по опубликованным товарам (см. Context), поэтому «Горелочные устройства» исчезнут из меню, сайдбара каталога и футера сами. Терм `gorelochnoe-ustroistvo` остаётся в базе пустым и невидимым.

**Это допущение, а не указание заказчика.** В рукописной правке сказано «убираем» / «убрать весь раздел» — без уточнения, снять с витрины или стереть из базы. Выбран обратимый вариант: видимый результат тот же, а вернуть раздел можно одним переключением статуса. Если нужно именно безвозвратное удаление — это правка одной строки в `tasks.md`, спецификация «Контент убранного раздела сохраняется и обратим» в `specs/catalog-visibility/spec.md` тогда снимается.

*Альтернатива:* удалить товар и терм. Отклонено как необратимое без бэкапа при одинаковом видимом результате.

### 4. Редиректы — хуком темы, а не `.htaccess` и не плагином

В `hooks_filters/` добавляется небольшой обработчик `template_redirect`, который отдаёт 301 на `/catalog` для `/products/arbat/` и `/product-category/gorelochnoe-ustroistvo/`.

*Альтернатива А:* `.htaccess`. Отклонено — production на nginx, файл просто не читается.
*Альтернатива Б:* плагин Redirection. Отклонено — новая зависимость, а правила лягут в базу, то есть снова вне git.
*Альтернатива В:* ничего, пусть будет 404. Отклонено — теряются внешние ссылки и позиции в поиске по запросу «арбат».

Список редиректов делаем явной таблицей «старый путь → новый» в одном файле, чтобы следующие снятия товаров дописывались туда же.

### 5. Баннер «Электрорезерв» пересобираем и кладём в медиатеку

Нужен файл 1154×400 с текстом «ЭЛЕКТРОРЕЗЕРВ / ПОДГОТОВКА ПОД УСТАНОВКУ ЭЛЕКТРИЧЕСКИХ ТЭНОВ» вместо украинского. Русский вариант этого же лого-локапа (иконка вилки + две строки) уже есть на сайте — внутри слайда `wp-content/uploads/2023/06/slide-1-scaled.jpg`, который как раз удаляется с главной задачей №1. Берём локап оттуда, собираем баннер в композиции оригинала (ТЭН слева, котёл справа), заливаем в медиатеку и меняем `data-src` в описании Житомир-9.

**Это тоже допущение.** Если у заказчика есть готовый русский баннер от производителя — он лучше пересборки, и тогда из задач остаётся только «загрузить и подменить ссылку».

*Альтернатива:* оставить хотлинк, но подменить его на русский файл на стороне `atem.ua`. Невозможно — чужой сервер.

### 6. После всех правок — сброс кеша страниц

Правки контента не появятся на сайте, пока не сброшен кеш WP-Optimize. Это обязательный шаг приёмки, а не опция.

## Risks / Trade-offs

- **Правки контента не версионируются — откат только руками.** → Перед началом снять резервную копию базы средствами хостинга; в `tasks.md` зафиксированы точные прежние значения (имена файлов слайдов, URL хотлинка), чтобы откатить вручную.
- **Видимость категории завязана на счётчик терма (`hide_empty`), который WordPress пересчитывает при смене статуса поста.** Если счётчик по какой-то причине не обновится, «Горелочные устройства» останутся в верхнем меню. → Проверяем все три места вывода отдельными пунктами приёмки; при залипании счётчика лечится пересохранением товара.
- **Кеш страниц покажет старую версию и создаст впечатление, что правка не применилась.** → Проверка только после сброса кеша и в приватном окне.
- **`watchOverflow: true` блокирует Swiper при одном слайде.** Теоретически заблокированный swiper может повлиять на отрисовку. → Проверяем, что единственный слайд виден и корректно масштабируется на десктопе и мобильном.
- **Редирект заработает только после деплоя темы** (push в `main` → FTP-экшен), то есть между правкой контента и деплоем старые URL какое-то время будут отдавать 404. → Сначала деплоим код, потом снимаем товар с публикации.
- **Пересобранный баннер может не попасть в фирменный стиль ATEM** (шрифт, кернинг). → Локап берём из существующего файла сайта, а не рисуем с нуля; итог показываем заказчику до публикации.
- **В production есть плагины, которых нет в репозитории** (WP-Optimize и, возможно, другие). FTP-синк удаляет только то, что сам раньше заливал, поэтому они не пострадают — но это значит, что состояние production шире репозитория и проверять надо на боевом сайте.

## Migration Plan

1. Резервная копия базы production.
2. Правка кода (`watchOverflow`, редиректы) → push в `main` → дождаться FTP-деплоя.
3. Правки контента в wp-admin: слайдер главной, статус АРБАТ, баннер Житомир-9.
4. Сброс кеша страниц.
5. Приёмка по сценариям из `specs/`.

**Откат:** код — реверт коммита и повторный деплой; контент — вернуть слайды в репитер, товару АРБАТ статус «Опубликовано», в описании Житомир-9 вернуть прежний `data-src` (значение записано в `tasks.md`).
